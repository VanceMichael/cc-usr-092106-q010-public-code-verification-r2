# 公众扫码来源核验后台：领域规则与架构约定

本文档把发布规则逐条映射到代码模块。当前代码库是**可执行的领域内核**（纯
Python 标准库、内存实现），不绑定 Web 框架与数据库；接口即生产边界，接
入层只需替换存储与投递实现。

## 1. 发布状态

权威事实经 `src/statuses.py:decide` 映射为且仅为五种可解释状态：

| 状态 | 触发条件 | 公众文案要点 |
| --- | --- | --- |
| `produced` 生产 | 有生产源头、无后续流转、无异常无控制 | 可确认生产来源 |
| `legit_flow` 合法流转 | 链路完整、机构持资质、无生效控制 | 来源与流转一致 |
| `recalled` 已召回 | 批次存在生效中的召回事件 | 停止使用并按指引处置 |
| `pending_review` 待复核 | 监管封存，或链路存在异常 | 以监管复核为准 |
| `unconfirmed` 无法确认 | 码未登记、权威源不可达 | 谨慎购买，可提交异议 |

结论携带 `reasons`（理由码）、`basis_event_ids`（依据节点）与
`data_version`（批次@修订号#判定时刻），保证每个页面结论都可解释、可复算。

**弱信号规则**：短时多地扫码只记 `weak_scan_signal_only` 理由，单独出现
绝不改变结论；只有权威链路自身异常才进入待复核。离线补传的异地记录不
参与异地统计（见 `ScanSignalCollector`）。

## 2. 隐私最小化（`src/privacy.py`）

- 权威节点分 `public_payload` 与 `restricted_payload`；后者（前购药人
  身份、经办人、侦办案件编号）永不进入公众视图，并有测试逐项断言。
- 机构只展示**类型 + 省级区域**（如"零售/医疗机构药房·河北"），不出现
  具体机构名称与许可编号。
- 封存/核查节点只给"监管核查中"摘要，无机构、无区域、无文号。
- 销售节点不附带任何公开细节；追溯码只以脱敏形式（前4后4）出现在页面。
- 更正理由、弱信号理由只供内部复核，不进公众视图。

## 3. 只追加的权威轨迹（`src/authority.py`）

- 事件只能追加；更正通过追加 `correction` 事件完成，被更正节点原貌保留
  并回填 `corrected_by`。
- 召回/封存被更正后视为解除，`active_control` 不再返回。
- 批次修订号 `batch_revision` 在每次影响该批的追加/更正时单调递增。
- `inspect` 检查：缺失源头、断链、成环、机构未登记、资质失效、控制后仍
  流转、销售后异常事件。

## 4. 版本感知缓存（`src/cache.py`）

- 正缓存条目绑定批次修订号，读取时比对，**权威更正/风险升级即精准失效**，
  不依赖 TTL；另提供权威推送到达时的 `invalidate_batch` 批量失效。
- 失效不等于删除：旧条目进入历史档案，含当时页面快照与**公开事件依据
  快照**（无受限字段），回答"此前页面当时为何给出旧结果"，并区分
  `risk_escalation` 与 `authority_update` 两种归因。
- 码不存在走独立负缓存，TTL 10 分钟（码可能被企业补报）。
- 权威源故障时可返回 `stale` 旧结论，但必须带"截至某时"标注，绝不伪装
  成实时结论；无旧结论可展示时返回"无法确认（来源暂不可用）"。

## 5. 入口分流（`src/verifier.py`）

| 情形 | 处理 |
| --- | --- |
| 重复扫码 | 缓存命中返回同一结论对象；幂等键重放不产生重复记录 |
| 离线补查 | 按原始扫码时间入账、幂等去重，不制造异地信号 |
| 恶意枚举 | 匿名令牌桶限频 + 窗口内"码不存在"熔断 30 分钟；残损输入不占配额；节流响应与正常结论同形，不泄露码是否登记 |
| 码不存在 | 事实性结论 → 无法确认（码未登记），短 TTL 负缓存 |
| 残损输入 | `DamagedCode` → 提示重扫，不查库、不缓存、不计数 |
| 权威源降级 | 先 stale 旧结论（带标注），否则无法确认 |

限频桶、扫码统计均使用不可逆散列令牌/指纹，不保存可识别身份。

## 6. 公众异议（`src/disputes.py`）

- 证据有类型白名单（jpg/png/pdf）与 10MB 上限，必须带完整性摘要，进入
  即标记隔离（`quarantined=True`），不参与任何自动判定。
- 异议只产生工单（received → in_review → accepted/rejected），评审期间
  权威库零写入。
- 采纳时由**具权威角色的复核人显式传入权威写操作闭包**才落库；公众输入
  不存在直达权威轨迹的代码路径。
- 每客户端每小时限 5 件，防渠道淹没。

## 7. 风险订阅通知（`src/subscriptions.py`）

- 仅显式订阅：扫码不产生订阅，须主动申请 + 渠道令牌二次确认。
- 批次结论变化时只通知：有效、未过期（180 天）、已确认、**码仍在影响
  集合内**、未收到过同结论签名通知的订阅者。
- 按批次结论签名去重，重发/多机房不产生重复通知；通知只含脱敏码与
  必要摘要，并记录数据版本供回溯。

## 生产落地边界

内存实现替换点：`AuthorityStore`（事件库 + CDC 推送批次变更）、
`VerificationCache`（Redis，键用码指纹）、`ScanSignalCollector`（流式
去身份统计）、`NotificationService`（真实渠道网关）。接入层负责把
权威推送与 `invalidate_batch`、`notify_batch_change` 串成同一事务/
出队顺序，先失效缓存再通知。
